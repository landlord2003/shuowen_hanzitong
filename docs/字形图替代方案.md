# 字形图替代方案（中研院下载被封后的解决路径）

> 背景：原定「换源 → 台湾中研院小學堂」路线，经实测**双向不可达**——台湾出口 geo-block（返回 Access Restricted）+ 海外直连也被 block。本文给出不依赖中研院的替代路径与实测可达性。

---

## 1. 现状与实测可达性矩阵（本沙箱实测，2026-09-08）

| 数据源 | 用途 | 本机实测 | 结论 |
|---|---|---|---|
| 中研院小學堂 `xiaoxue.iis.sinica.edu.tw` | 甲骨/金文/篆位图 | Access Restricted（geo-block） | ❌ 死路 |
| 中研院 `cdpx.iis.sinica.edu.tw/dbdownload` | 安装包 | 502 | ❌ 死路 |
| Wikimedia Commons | 公版古文字图 | HTTP 000（block） | ❌ 本机不可达 |
| Internet Archive `archive.org` | 公版原典扫描 | 502（tunnel failed） | ❌ 本机不可达 |
| **BabelStone Han 字体** `babelstone.co.uk` | 古文字字形（字体渲染） | **HTTP 200，可分段下载** | ✅ **本机可落地** |
| **cjkvi-ids (GitHub raw)** | IDS 字形结构树 | HEAD 200，但 2.1MB 拉到 664KB 即 timeout | 🟡 能连但不稳，需可达网络重试 |

**关键结论**：中研院这条路彻底堵死，但 **BabelStone 字体本机可下、可商用**，cjkvi-ids 能连（不稳）。所以「字形图」问题没死，只是要换技术路线。

---

## 2. 四条替代路径详评

### 路径 A（推荐·最快·本机可落地）：BabelStone Han 字体渲染
- **来源**：`https://www.babelstone.co.uk/Fonts/Download/BabelStoneHan-16.0.3.zip`（已验证 HTTP 200）
- **授权**：Arphic Public License（文鼎公共许可证）—— **可个人/商业使用、可修改、可分发**；改字体名即可（不能用 "BabelStone" 字样）。
- **覆盖**：6 万+ 汉字，明确包含「甲骨 / 金文 / 简牍 / 帛书等早期文献学术转写专用字符」（Unicode 扩展区古文字码位）。
- **实现**：App 内置字体 + Canvas 渲染字形，**直接替代 `dataset.bin` 位图方案**——不需要打包位图、不需要中研院。
- **优点**：零外部依赖、即时、可商用、本机就能做、覆盖广。
- **缺点（诚实）**：① BabelStone 的古文字是「学术转写体」（规范化、非真拓片原貌）；② 只有 Unicode 已编码的古文字码位才有字形，很多未编码字无甲骨/金文形态；③ **覆盖率需实测字体 cmap 确认**（下载后用 fonttools 看含多少甲骨/金文/篆码位）。
- **适用性**：能让 App 从「纯文字」升级到「显示规范化古文字形态」，是性价比最高的即时方案。

### 路径 B（最合规·最真·老吴原话兜底）：自绘公版拓片 SVG
- **思路**（即用户最初指示「不行就自绘公版拓片 SVG」）：在**可达网络**取公版原典扫描 → 裁剪/矢量化 → 打包进 `dataset.bin`。
- **候选公版源（作者去世 >100 年，公版）**：
  - 甲骨文：罗振玉《殷虚书契》(1913)、孙诒让《契文举例》等早期著录
  - 小篆：段玉裁《說文解字注》篆字（清，公版）
  - 公版图站：Wikimedia Commons / Internet Archive / Wikisource（任一可达即可，**非中研院**）
- **优点**：真迹、公版、最合规、视觉最佳，完全契合用户最初设想。
- **缺点**：工程重（扫描提取/矢量化），且 Commons/IA 本机 block，**需在可达网络环境取**（放行概率高于中研院，因为非台湾特定站点）。
- **授权**：公版原典扫描本身无版权；但**扫描件版权归扫描者**——需选「明确公版/CC0 发布」的源（如 Wikisource 公版扫描），勿用未声明授权的商业库。

### 路径 C（零下载·开源兜底）：cjkvi-ids 结构图
- **来源**：`github.com/cjkvi/cjkvi-ids`（GPLv2），每字给 IDS 部件分解（`U+5730 地 ⿰土也`）。
- **实现**：App 渲染 IDS 结构树作为「字形结构图」，任何字都能显示，绝不空白。
- **优点**：开源、零下载依赖、覆盖 9 万+ 字、本机可连。
- **缺点**：只是「六书结构示意」，非甲骨/金文原貌，视觉最弱；GPLv2 传染性（App 若静态链接需留意）。
- **角色**：作为 A/B 任一缺失字的**兜底可视化**，保证界面不空。

### 路径 D（其他开源古文字字体，授权需警惕）
- ❌ **方正甲骨文字体**（3230 字）：部分站点标「免费可商用」是**误导**——方正为商业授权，商用需购买。**禁用**。
- ⚠️ 华东师大「花园庄东地甲骨文/金文/楚简/說文篆体」字体：授权**不明**，不推荐商用。
- 🟡 「全字庫說文解字」(8070 字) / 「崇羲篆體」(6916 字)：源自台湾全字库/小学堂，**授权待查**（可能 CC 或政府公开资料），查实后可考虑。
- ✅ 香港民间字集（OFL 自由商用）：但这是传承宋体，非古文字，不适用。

## 4. 对 App 架构的影响

原 `dataset.bin`（CEDS0002 位图容器）+ `DatasetReader` 不改，新增两条渲染通道：

1. **字体通道**：`index.html` 内置 `@font-face BabelStoneHan` + Canvas 按「甲骨/金文/篆/隶/楷」码位渲染字形 → 替代缺图字的位图。
2. **IDS 通道**：内置 `ids.txt`（cjkvi，GPLv2）→ 渲染部件树兜底。
3. **位图通道**：保留，待路径 B 补图后 `dataset.bin` 自动优先。

优先级：位图(bin) > 字体(BabelStone) > IDS 结构图。

## 7. 更正（2026-09-08）：A 路线 BabelStone 实测不可行，已改走 GlyphWiki「字源」

> ⚠️ **重要更正**：第 2 节「路径 A」与第 6 节落地项需作废。BabelStone 字体**本机可下载**（HTTP 200 可达，授权 Arphic 可商用，均属实），但**实测无法用于从普通汉字渲染古文字字形**。

### 7.1 BabelStone 致命缺陷（实测）

- 下载并验证 `BabelStoneHanPUA.ttf`（v16，约 4.9MB，含 6024 个 PUA 码位 U+E080–F8DF）。
- 用 fonttools 检查 cmap：**仅含 6024 个 PUA 码位，普通汉字（CJK 统一表意文字区）无任何对应字形**。
- 即：BabelStone 的「甲骨/金文/简牍/帛书」字形都挂在 **PUA 私有区码位**上，**完全没有「标准汉字 → 古字形」的映射表**。
- 结论：从「水」「鼎」等正常汉字文本出发，**无法**通过 BabelStone 渲染出对应的古文字形态。除非另造一份「标准字→PUA 码位」映射表（工作量等同自绘，且 BabelStone 古字形本身也是学术转写体），否则此路不通。
- 故 **A 路线停用 BabelStone 方案**，字体文件已从仓库排除（见 `.gitignore` 的 `data/fonts/`）。

### 7.2 A 路线现行方案：GlyphWiki「字源」阶段（已落地 ✅）

- **来源**：GlyphWiki.org（HTTP 200 本机直连可达），规范名 `uXXXX`（小写 hex）取 SVG。
- **授权**：**CC BY-SA 2.1 JP**——可商用，但**必须署名 + 衍生同授权**；已固化到 `data/dataset-reader.js` 注释、App 页脚与演变区 `src-mini` 署名。
- **诚实标注**：GlyphWiki 给出的是该字的标准/旧字形（historical form），**并非严格的甲骨/金文/篆文真迹**，故在 App 中**单独标注为「字源」阶段**，绝不冒充实物的「篆文」。
- **实现**：`tools/rubbing_pipeline/adapters/glyphwiki.py`（并发抓取 + resvg 栅格化）+ `pipeline.py` 打包进 `data/dataset.bin`；App 端已在 `dataset-reader.js` 增加 `glyphwiki` 的 `SCRIPT_ORDER` / `SCRIPT_METADATA`，并在 `build_web.py` 的演变 `order` 数组首位接入。
- **产物**：`data/dataset.bin`（已生成，覆盖全 8105 字中 GlyphWiki 有字形的部分）；缺字 App 自动回退繁/简纯文字。
